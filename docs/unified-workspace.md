# Jobs, documents, and change orders

The existing review dashboard remains the entry screen. **Jobs & Documents** opens saved permanent jobs; **Import jobs** continues to replace only the autocomplete directory. Each job has Job Details, Documents, Change Requests, and Estimate Intake.

## Job and document workflow

- Create a job manually or start from a directory entry. Its workspace ID does not depend on directory IDs or a CSV import.
- Edit customer/property, insurance, financials, mortgage, team/branch, checklist, and production notes. Each edit commits to IndexedDB before it is reported saved on the device. Shared synchronization runs in the shell after navigation.
- Original contract and previous authorized changes are independent from approved RCV. Payments retain the original generator's 50/25/25 split of approved RCV, using exact cents and a remainder balance.
- Generate seven production documents, an eight-page combined packet, or a ZIP. Use the existing customer change-order editor for the eighth document type. Packets can include that request's saved, current PDF; they then have nine pages.
- Save generated documents or a combined packet to the job. Bytes, identifiers, and mutation identities persist locally until the server confirms the upload. Earlier PDFs remain in history and are identified when job details change.
- Start a change request from the job to prefill its snapshot. Existing requests can be connected using **Connect job details & documents**, including completed requests; this changes only their workspace link. Later master-job edits do not rewrite saved request snapshots or estimator corrections.

Concurrent tabs merge edits to different fields. Conflicting values are kept as two device drafts until a person chooses. Server revision conflicts also preserve the device version for explicit resolution. A successful local save is never described as confirmed cloud synchronization.

## Migration

In the original `haysdocuments-2` app, open Jobs and select **Export for combined app**. The export includes the full remote library plus every cached job, device draft, and queued action. It rejects a truncated remote response, strips credentials, and never clears the source stores.

In the combined app, choose **Jobs & Documents → Import document jobs** and select the JSON. Review matches and conflicts, choose explicit destinations for duplicate job numbers, and import. Existing nonblank corrections, zeros, and false values are preserved. Repeat imports skip already imported versions; changed source data becomes a separate review copy. Original records and Drive references are retained in migration metadata. Pending source deletions are review entries, not instructions to delete target records.

The customer-reference CSV remains separate from both the job directory and saved workspaces. AI estimate analysis uses only the uploaded/pasted document, validates the response, and runs through Apps Script. It never approves the final customer change price.

## Backend contract

Existing request actions remain compatible. The following additional actions are JSON POST bodies sent with `Content-Type: text/plain;charset=utf-8`:

| Action | Inputs | Success fields |
| --- | --- | --- |
| `listWorkspaces` | — | `workspaces` |
| `openWorkspace` | `workspaceId` | `workspace` |
| `saveWorkspace` | `workspace`, `expectedRevision`, `mutationId` | `workspace`, `mutation` |
| `linkRequestWorkspace` | `id`, `workspaceId`, `expectedRevision`, `mutationId` | `request` |
| `listJobDocuments` | `workspaceId` | `documents` |
| `saveJobDocument` | workspace/document/mutation IDs, kind, input fingerprint, template version, PDF file payload | `document` |
| `fetchJobDocument` | `workspaceId`, `documentId` | `name`, `mimeType`, base64 `data` |
| `getCustomerReference` | — | `reference` |
| `replaceCustomerReference` | `customers`, `fileName` | `reference` |
| `analyzeIntake` | `rawText` | `analysis` |

Success always requires `ok: true`; HTTP 200 alone is insufficient. New `Workspaces`, `JobDocuments`, and `CustomerReference` sheets are separate from `Jobs` and `Requests`. Workspaces and PDFs use scoped Drive folders; revision snapshots and mutation receipts make retries recoverable without duplicating files.

```powershell
npm test
npm run typecheck
npm run build
npm run fixtures
npm run test:browser
```

Browser tests intercept the Apps Script requests with the real backend sandbox; they do not write test data to the live spreadsheet. `PLAYWRIGHT_PORT` selects an independent server port. PDF tests read actual generated bytes, checklist fields, Unicode text, and page counts. In `haysdocuments-2`, run `npm run workspace:export:test` and `npm run lint` to verify the source exporter independently.

October 17 results: 105 unit/backend/PDF tests and 2 source-export tests pass; all 61 browser scenarios pass against the production build (59 in the full run, followed by the two corrected production-harness cases). The font-delay interceptor now accepts Vite's hashed asset name. The read-only layout case allows real service worker registration; mutation/recovery cases block workers to guarantee sandbox API interception. Typecheck, lint, production/PWA build, and deployment preflight pass. Remaining PDF.js eval and chunk-size notices come from existing bundled dependencies. `PLAYWRIGHT_PORT` and `PLAYWRIGHT_PREVIEW` are test-runner settings and do not belong in Vercel runtime settings.

For an isolated local development preview:

